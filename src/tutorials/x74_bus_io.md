## 1. CPU 与设备的鸿沟

CPU 是纳秒级的心脏，外设是毫秒级的器官——**磁盘一次 I/O ≈ 百万 CPU 周期**。I/O 系统的全部设计围绕一个问题：

> **CPU 如何与慢速设备通信，且不把宝贵的 CPU 时间浪费在等待上？**

演进主线：**轮询 → 中断 → DMA**——每一步都在把"CPU 亲自等待/搬运"的活外包出去。

## 2. 总线的演化：从共享马路到立交桥

| 时代 | 总线 | 特点 |
| --- | --- | --- |
| 早期 | ISA/VLB 共享总线 | 所有设备共用一组线，同时刻只能一对设备通信（总线仲裁） |
| PCI | 并行共享 | 32/64 位并行，33/66MHz，带宽上限明显 |
| **PCIe** | **串行点对点** | 每设备独立链路，无总线冲突 |

**PCIe 的关键转变**：不再共享——每个设备到根复合体（Root Complex）有独立的**链路（link）**，每条链路由 1/4/8/16 条 **lane** 组成（x1/x4/x8/x16）。PCIe 3.0 单 lane ≈ 8 GT/s ≈ 984 MB/s——**x16 ≈ 16 GB/s**（显卡插槽的标准带宽）。

GPU、NVMe 卡、网卡插的就是不同 lane 数的插槽。x16 插槽插 x4 卡可以（降速），x4 插槽插 x16 卡不行（lane 不够）——**装机性能瓶颈的第一排查项**（NVMe 盘跑不满速先查插槽 lane 数）。

## 3. I/O 控制三方式：轮询、中断、DMA

### ① 轮询（Programmed I/O）
```c
while ((status = read_status()) != READY);   // 死等
read_data();
```
CPU 全程空转——简单但浪费（设备慢于 CPU 100 万倍）。仅适合**高速且确定就绪**的设备。

### ② 中断（Interrupt-driven I/O）
设备准备好后**主动发中断信号**打断 CPU——CPU 平时干别的：

```
设备就绪 → 中断控制器（如 APIC）→ CPU 收到中断 →
保存现场 → 查中断向量表 → 跳转中断处理程序 → 处理 → 恢复现场
```

**中断向量表**：每个中断号对应一个处理程序入口。**上下半部**（Linux）：上半部快速响应（中断关闭，做最少的事）注册下半部（softirq/tasklet），耗时的处理放下半部——**减少中断关闭时间**是响应性的关键。

**中断成本**：每次中断 ≈ 上下文切换 + 缓存污染（数百周期到微秒）。**高频小包网卡**（每包一中断）会中断风暴——解法：**中断合并**（攒一批再触发）或 **NAPI 轮询切换**（高流量时干脆改轮询）。**中断亲和性**（绑核）让网卡中断固定在同一核处理，缓存友好。

### ③ DMA（直接内存访问）
中断模式下数据搬运**还是 CPU 亲手干**（设备寄存器 → CPU → 内存，逐字）。**DMA 控制器**接管搬运：CPU 只下发"源地址、目标地址、长度"，DMA 独立搬完发一个中断——CPU 全程零参与：

```
CPU: 配置 DMA 控制器 → 继续干别的
DMA: 设备 → 内存 直接搬运（不经过 CPU）
DMA 完成中断 → CPU 处理结果
```

**适用判据**：数据量大必用 DMA（磁盘/网卡/显卡）；数据量小（几个字节）DMA 配置开销反而不划算。NVMe SSD 的高性能一半来自 DMA + 多队列。

## 4. CPU 如何"看到"设备：MMIO 与端口 I/O

设备寄存器映射进 CPU 可寻址空间的两种方式：

| 方式 | 机制 | 平台 |
| --- | --- | --- |
| 内存映射 I/O（MMIO） | 设备寄存器映射为内存地址，用 mov 读写 | 现代主流（PCIe BAR 空间） |
| 端口映射 I/O（PMIO） | 独立 I/O 地址空间，专用 in/out 指令 | x86 传统设备（遗留） |

**MMIO 的语义陷阱**：指向设备的"内存"读写有副作用（读 FIFO = 取走数据）——编译器可能优化掉"冗余读取"！必须用 `volatile`（C）或 `readl/writel`（Linux 内核 API）告诉编译器别动。显卡把帧缓冲 MMIO 进地址空间——写那个地址 = 画像素。

## 5. 存储演化的 I/O 视角：SATA → NVMe

```
SATA（AHCI 协议）: 单队列、深 32 → 一个 SATA 盘排队等单一 CPU 核处理
NVMe（PCIe 直连）: 64K 队列 × 64K 深度 → 多核并行处理，I/O 路径大减
```

机械盘时代队列深没意义（磁头是串行的）；**NVMe 闪存并发无寻道惩罚**——队列成为吞吐的杠杆。NVMe 盘 4K 随机读远超 SATA 的原因不只是闪存快，更是 **I/O 路径重构**（PCIe 直连 + 多队列 + 更轻的协议栈）。

## 6. 陷阱速查表

| 现象 | 原因 | 修法 |
| --- | --- | --- |
| NVMe 跑分不满速 | 插在 x4/x2 lane 插槽 | 查主板 lane 分配表 |
| 高流量时 CPU 中断风暴 | 每包一中断 | 中断合并 / NAPI 轮询 / 中断绑核 |
| 设备寄存器读两次值不同 | 设备寄存器有副作用 | volatile / 内核 I/O API |
| DMA 数据没写完就被读 | CPU 与 DMA 无同步 | 内存屏障 / 完成中断后处理 |
| 共享中断号设备互相干扰 | 多设备共享一条中断线 | MSI（消息信号中断，每设备独立向量） |
