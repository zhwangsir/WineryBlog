## 1. 计算理论回答的两个终极问题

1. **可计算性**：哪些问题原则上能被算法解决？（能力边界）
2. **复杂度**：可解的问题里，哪些"实际可行"？（资源边界）

这不是纯理论——正则表达式背后的自动机、编译器的文法分析、"这个问题是 NP 难的别暴力了"的工程判断，全部源自这套理论。

## 2. 自动机层级：四类语言的识别能力

乔姆斯基层级（语言包含关系逐级递增）：

| 层级 | 自动机 | 识别的语言 | 例 |
| --- | --- | --- | --- |
| 3 型 正则 | 有限状态机（DFA/NFA） | a*b*、可正则表达式的语言 | 词法、协议状态 |
| 2 型 上下文无关 | 下推自动机（PDA，带栈） | 括号配对、aⁿbⁿ | 程序语言语法（BNF 文法） |
| 1 型 上下文有关 | 线性有界自动机 | aⁿbⁿcⁿ | — |
| 0 型 递归可枚举 | 图灵机 | 一切可计算语言 | — |

**正则语言的死穴**：数匹配——aⁿbⁿ 需要"记住 n 有多大"，有限状态机没有无限记忆（栈才有）——所以**不能用正则表达式匹配任意深度的嵌套括号**。这就是 HTML/JSON 解析器不用正则的数学原因（正则能匹配部分受限模式，通用嵌套不行）。

**DFA ≡ NFA**：NFA（非确定性，可多路并行猜测）的表达力与 DFA 等价（子集构造法转换，状态数可能指数爆炸）——正则引擎实现选择 DFA（快但构造贵）或 NFA 回溯（构造快但可能回溯爆炸——正是站内《正则表达式精通》讲的 ReDoS 根源）。

## 3. 图灵机与丘奇-图灵论题

图灵机 = 无限纸带 + 读写头 + 有限状态控制——**简单到可以数学分析，强到能模拟一切计算**。

**丘奇-图灵论题**（论题而非定理）：一切"直觉上可计算"的函数都可被图灵机计算。所有等价模型（lambda 演算、递归函数、真实计算机）都不超出图灵机的边界——因此"可计算"有了严格定义。

## 4. 不可判定性：停机问题

**停机问题**：能否写一个程序 H(P, x) 判断"程序 P 在输入 x 上会不会停机"？——**不可判定**（不存在这样的程序）。

对角线反证（精华三行）：

```text
假设 H 存在 → 构造反例程序 D(P)：
  if H(P, P) 说"会停" → D 进入死循环
  else               → D 立即停机
把 D 自己代入：H(D, D) 说"会停" → D 死循环 → 矛盾
              H(D, D) 说"不停" → D 停机   → 矛盾
∴ H 不存在
```

**推论雪崩**：停机问题归约出无数不可判定问题——程序是否有内存泄漏？两段代码是否等价？程序会不会输出特定字符串？（Rice 定理：任何"程序行为语义"的非平凡性质都不可判定。）

**工程含义**：完美的静态分析器不存在——所有 linter/杀毒/形式验证都在做**近似**（保守：宁可漏报不误报，或反之）。

## 5. P 与 NP：可解问题的复杂度分层

- **P**：存在多项式时间**求解**算法的判定问题（排序 O(n log n)、最短路 O(V+E)）
- **NP**：解的**正确性可在多项式时间验证**的问题（数独给个解一眼能验；哈密顿路径给个序列能验）

P ⊆ NP 显然（能解就能验）。**P=NP?** 是千禧年百万美元难题——普遍猜想 P≠NP（验证远比求解容易）。

**NP 完全（NP-complete）**：NP 中"最难"的问题——任何 NP 问题都能多项式归约到它。Cook-Levin 定理证明 **SAT（布尔可满足性）是第一个 NP 完全问题**；此后经归约链证明数千问题 NP 完全：**3SAT、旅行商（判定版）、背包、图着色、子集和、哈密顿路径、CLIQUE**……

**归约的实用读法**：A 归约到 B（A ≤p B）意为"B 至少与 A 一样难"——若 B 有多项式算法，则 A 也有。遇到新问题，先找已知 NP 完全问题归约过来——证明了就别浪费时间找精确多项式算法。

## 6. 遇到 NP 难问题怎么办（工程实战）

| 策略 | 思路 | 代价 |
| --- | --- | --- |
| **近似算法** | 有保证的次优解（如顶点覆盖 2 近似） | 解非最优但误差有界 |
| **启发式/元启发** | 贪心、模拟退火、遗传算法 | 无保证，经验调参 |
| **特例求解** | 实际输入的受限结构常是多项式的（区间调度、树上的问题） | 挖掘问题特殊结构 |
| **参数化复杂度** | 按 k（如解的大小）指数、n 多项式（FPT） | k 小时实用 |
| **指数但快** | 2^n 的 n≤40 可跑（位运算/剪枝/记忆化） | 小规模实例 |

**案例**：任务排期本质是 NP 难的调度——工程上用贪心（优先级排序）+ 局部搜索（交换改进）的组合，多数场景足够；关键系统再加近似算法的质量保证。

## 7. 陷阱速查表

| 现象 | 原因 | 修法 |
| --- | --- | --- |
| 用正则解析嵌套结构 | 正则=正则语言，无栈 | 用递归下降/解析器 |
| 以为"没找到多项式算法=不存在" | 可能只是没人找到 | 证明 NP 难（归约）才有结论 |
| NP 难问题暴力枚举超时 | 搜索空间指数 | 近似/剪枝/记忆化/退火 |
| 把 NP 完全当"完全不可解" | 指数算法对 n≤40 实用 | 位运算压缩 DP / 分支限界 |
| 验证很慢就断言不是 NP | NP 定义是"可验证"的类 | 检查验证算法是否多项式 |
