## 1. HCI 是什么：CS2023 的独立知识域

人机交互（Human-Computer Interaction）在 CS2023 课程体系中是**独立知识域**——横跨计算机科学、认知心理学与设计学。它的核心命题：

> **技术为人服务——理解人的认知与行为模式，才能设计出人不犯错、不费力、不困惑的界面。**

工程视角的价值：可用性问题 = 用户流失 = 直接的商业损失。同一个功能，可用性优化前后转化率可以有数倍差异——**HCI 不是美工，是可量化的工程学科**。

## 2. Norman 设计原则：认知心理学的界面化

Don Norman（《设计心理学》作者）的原则源自对人类认知的研究：

| 原则 | 含义 | 反例 → 修法 |
| --- | --- | --- |
| **可见性** | 功能一眼可见，不用记忆 | 功能藏在三级菜单 → 关键操作上浮 |
| **反馈** | 每个操作都有即时、清晰的响应 | 点击无响应 → loading 态 + 结果提示 |
| **约束** | 用设计限制错误操作的可能 | 圆孔方插头 → 接口形状约束 |
| **映射** | 控制器与效果的关系自然直观 | 楼层按钮排列随意 → 按空间布局排列 |
| **一致性** | 同类操作同样表现 | 同功能不同图标 → 统一组件库 |
| **可供性** | 外观暗示用途（门把手暗示拉） | 看不出能否点击的按钮 → 阴影/形状暗示 |

**核心思想**：好的设计让人**不犯错误**（约束），而不是犯了错误再提示（错误消息是设计失败的补偿）。

## 3. Nielsen 十大可用性启发式（精选六条）

Jakob Nielsen 的启发式评估清单是业界最常用的快速审查框架：

1. **系统状态可见**：让用户知道系统在干什么（进度条、面包屑、当前步骤高亮）
2. **匹配真实世界**：用用户的语言而非系统术语（"404 错误" → "页面找不到了"）
3. **用户控制与自由**：支持撤销/重做/退出——**误操作必须有后悔药**
4. **一致性与标准**：平台惯例优先于自家创意（下划线=链接、齿轮=设置）
5. **预防错误**：好过优雅的错误信息（日期选择器好过让人手输日期格式）
6. **识别优于回忆**：让用户选择而非记忆（下拉选项好过让用户背格式）

**启发式评估法**：3-5 名评审各自独立对照清单审查界面，汇总问题按严重度分级——**半小时发现 70%+ 的可用性问题**，成本远低于用户测试。

## 4. 认知负荷：三条定量定律

| 定律 | 内容 | 设计推论 |
| --- | --- | --- |
| **希克定律** | 选择越多，决策时间越长（对数增长） | 菜单 ≤7 项；高频操作分组；避免一屏 30 个选项 |
| **费茨定律** | 点击目标越大越近，越快命中 | 关键按钮大且近；危险按钮远离常用按钮；边缘/角落是"无限大"目标 |
| **米勒法则** | 工作记忆约 7±2 组块 | 信息分组（电话号码分段）；渐进披露 |

**工程应用**：表单设计——分组分步（降低单屏负荷）、内联校验（即时反馈）、必填标注（预期管理）、默认值（减少输入）。

## 5. 可访问性（a11y）：WCAG 与工程实践

**15% 的人群有某种残障**（视觉/听觉/运动/认知）——可访问性是道德、法律（各国无障碍法规）与 SEO/可用性的三重收益。

**WCAG 四原则（POUR）**与工程实践对照：

| 原则 | 实践 |
| --- | --- |
| 可感知（Perceivable） | 图片 alt 文本；视频字幕；对比度 ≥4.5:1（文字） |
| 可操作（Operable） | 全键盘可导航（Tab 顺序）；焦点可见；无纯悬停交互 |
| 可理解（Understandable） | 语义 HTML（button/link 正确用）；表单 label 关联 |
| 健壮（Robust） | 正确的 ARIA 角色；与屏幕阅读器兼容 |

```html
<!-- ✗ 反例：div 假按钮——屏幕阅读器不识别、不可 Tab、不回车触发 -->
<div class="btn" onclick="save()">保存</div>

<!-- ✓ 正例：语义按钮——全部免费获得可访问性 -->
<button type="button" onclick="save()">保存</button>
```

**用对语义 HTML 就是 80% 的可访问性**——ARIA 属性是补丁不是替代（"No ARIA is better than bad ARIA"）。测试工具：axe（自动化扫描）+ 键盘手动走查 + 屏幕阅读器抽测。

## 6. 用户研究：最小成本的验证

- **可用性测试**：5 名用户即可发现 ~85% 的可用性问题（Nielsen 曲线：前 5 个用户边际收益最高）——给任务（"找到并购买 X"）观察用户操作，**不提示、不代劳**
- **发声思考**：让用户边操作边说想法——暴露"为什么卡住"的认知过程
- **A/B 测试**：定量验证（见站内《概率统计与信息论》的假设检验）
- **数据分析**：漏斗（哪一步流失）、热图（哪里被点）——定位问题页面后再定性研究

**流程**：定性发现问题（测试/启发式）→ 改进 → 定量验证效果（A/B）——定性找"为什么"，定量证"值多少"。

## 7. 陷阱速查表

| 现象 | 原因 | 修法 |
| --- | --- | --- |
| 用户不知道能点 | 可供性缺失 | 语义元素 + 视觉暗示 |
| 提交后没任何反应 | 反馈缺失 | loading/成功/失败三态 |
| 删除无法撤销 | 无约束无后悔药 | 二次确认 + 撤销机制（回收站） |
| 表单提交才报错 | 校验滞后 | 内联即时校验 |
| 键盘用户无法操作 | 纯 div+onclick | 语义 HTML + focus 管理 |
| 对比度低看不见文字 | 设计只顾美观 | WCAG 对比度工具检查 |
