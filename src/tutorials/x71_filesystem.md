## 1. 文件系统视图 vs 磁盘真相

用户看到的：路径树、`ls`、权限位。磁盘上的真相：**块设备 = 固定大小块（通常 4KB）的数组**，文件系统负责把"文件/目录"语义映射到块上。

文件系统的三件套职责：
1. **管理结构**：目录树如何存、空闲块如何记账
2. **文件数据**：一个文件的块散落在磁盘哪里
3. **一致性**：断电/崩溃后结构不损坏（日志）

## 2. inode：元数据与数据的分离

Unix 文件系统的经典设计（ext 家族延续）：

```
inode（索引节点）：文件的"身份证"
  - 类型、权限、大小
  - 所有者、时间戳（mtime/ctime/atime）
  - 块指针：[直接块 ×12 | 一级间接 | 二级间接 | 三级间接]
  - 不存文件名！

目录项（dentry）：文件名 → inode 号 的映射表
  - 目录本身是"装 dentry 的特殊文件"
```

**为什么分离**：硬链接（两个文件名指向同一 inode）、同一 inode 换名不换数据、目录只管名字不管内容。`stat` 看 inode 号——两个硬链接 inode 号相同。

**块指针的规模**：12 个直接块（48KB 内秒读）+ 间接块索引——小文件快，大文件靠间接层。ext4 改用 **extent**（连续块区间描述符），大文件只需很少的 extent 就能描述几 GB。

## 3. 空闲空间管理

| 方案 | 机制 | 特点 |
| --- | --- | --- |
| 位图（ext2） | 每块 1 bit 标记空闲 | 直观，扫描找连续块 |
| 空闲链表（FAT） | 空闲块串成链 | 简单，难找连续大块 |
| 分组（ext4） | 按块组划分，组内独立管理 | 局部性：inode 与数据块就近 |

**为什么关心连续性**：机械盘顺序读远快于随机读；SSD 虽无寻道，连续写也少映射开销。文件系统努力把"一个文件的块"放得靠近——**局部性原理在存储层的体现**。

## 4. 目录与路径解析

```bash
ls /home/winery/notes.txt
# 内核解析过程：
# 1. 读根目录 inode → 找 "home" 的 dentry → inode 号
# 2. 读 home 的 inode → 找 "winery" → inode 号
# 3. 读 winery 的 inode → 找 "notes.txt" → inode 号
# 4. 读 notes.txt inode → 拿块指针 → 读数据
```

**路径缓存（dcache）**：最近解析过的路径段缓存在内存——重复访问免磁盘。`dentry` 结构就是这个缓存的条目（`/proc/slabinfo` 可见 dentry 占用）。

## 5. 崩溃一致性：为什么断电会丢数据

多步操作不是原子的——写文件的顺序若为：

```
① 分配块给新数据  ② 写数据  ③ 更新 inode 大小  ④ 更新目录项
```

任意两步之间断电 → 结构损坏（指向空块的 inode、大小为 0 但占块的文件）。早期文件系统（FAT）会直接 `fsck` 扫全盘修复——**慢且可能误删**。

## 6. 日志文件系统（journaling）：现代标配

把"要做的改变"先**顺序写入日志区**，完成后才动真实结构——崩溃后重放日志即可恢复：

```
正常：prepare → 写日志（事务提交点）→ 应用到真实结构 → 清日志标记
崩溃：重启 → 看日志尾部 → 已提交的重放，未提交的丢弃
```

三种日志模式（ext4 可配）：

| 模式 | 记什么 | 安全性 | 速度 |
| --- | --- | --- | --- |
| writeback | 只记数据块指针，顺序不保证 | 数据可能旧但结构不坏 | 最快 |
| ordered（默认） | 先写数据再记元数据 | 数据+结构基本一致 | 中 |
| journal | 数据+元数据全记 | 最安全 | 最慢 |

`fsck` 从"每次开机必跑"变成"偶尔抽查"——这就是日志的价值。

## 7. 文件操作的落盘语义

```c
write(fd, buf, n);        // 只进页缓存（page cache）——返回≠落盘！
fsync(fd);                // 等数据+元数据写到磁盘
fdatasync(fd);            // 只等数据（元数据如大小可后补）
```

**write 后立即断电 = 数据丢失**是正常语义，不是 bug——数据库用 `fsync`（WAL）保证持久性，应用层的"保存成功"提示应基于 fsync 之后。

`O_DIRECT` 绕过页缓存（数据库自己做缓存时用，避免双重缓存）。

## 8. 现代文件系统一览

| FS | 特点 |
| --- | --- |
| ext4 | Linux 默认，稳定，extent + 日志 |
| XFS | 大文件/大并发优秀（企业级） |
| Btrfs/ZFS | 写时复制、快照、校验和（数据自愈） |
| F2FS | 为闪存设计（手机 eMMC/UFS） |
| NTFS | Windows，MFT 元数据表 |
| exFAT | 跨平台闪存（无日志） |

**写时复制（COW）文件系统**（ZFS/Btrfs）：写新数据不覆盖旧块——天然快照 + 崩溃一致性 + 校验和防静默损坏，代价是写放大与空间管理复杂。

## 9. 陷阱速查表

| 现象 | 原因 | 修法 |
| --- | --- | --- |
| write 返回成功但断电丢数据 | 页缓存未 fsync | 关键写 fsync/用日志型 DB |
| 硬链接删一个文件还在 | 只删了 dentry，inode 引用计数 >0 | 理解 link count；stat 看链接数 |
| df 与 du 不一致 | 已删除文件仍被进程持有 | lsof +D 找占用者删句柄 |
| 大文件写入越来越慢 | 碎片 / 磁盘将满 | fsck/整理；查 inode 与块余量 |
| 容器删文件空间不释放 | 文件被打开的 fd 占着 | 重启容器或 truncate 被占文件 |
