## 1. 虚拟内存解决的两个根本问题

1. **隔离**：每个进程都以为独占全部内存（虚拟地址空间），物理内存由 OS 统一分配——进程崩了只丢自己
2. **超量使用**：程序可以用比物理内存大得多的地址空间——"部分在内存、部分在磁盘"的幻觉

机制核心：**MMU（内存管理单元）**——CPU 里的硬件模块，把虚拟地址实时翻译成物理地址，翻译失败触发**缺页异常**交给内核处理。

## 2. 分页：固定大小的翻译单元

把虚拟空间切成固定大小的**页**（page，通常 4KB），物理内存切成同样大小的**页框**（frame）：

```
虚拟地址 = [页号 | 页内偏移]
           页号 → 查页表 → 物理页框号
           物理地址 = [页框号 | 页内偏移]     ← 偏移不变！
```

**为什么固定大小而不是可变分段**：分段有外部碎片（内存被切碎成小洞）；分页大小统一，页框直接从空闲列表取，无外部碎片。代价是**内部碎片**（进程最后一页装不满，平均浪费半页）——可接受的折中。

页表项（PTE）除了页框号还有标志位：**存在位**（在内存）、**读写位**（写保护）、**用户位**（用户态可访问）、**访问位/脏位**（给置换算法用）。

## 3. 页表放在哪：从单级到多级

**问题**：64 位地址空间若单级页表（每 4KB 页一条 8 字节 PTE），需 2^52 条目——16PB，荒谬。解法按层裁剪：

**两级页表（x86 经典）**：

```
虚拟地址 = [页目录号 | 页表号 | 页内偏移]
页目录（1024 项）→ 页表（1024 项）→ 页框
只给"用过的区域"建页表——程序大范围的地址空洞不占物理内存
```

**多级/倒排（现代 x86-64 四级、ARMv8 三级）**：层级越多，单级表越小；且只有实际访问的路径才分配物理页（按需建表）。

**页表本身也要加速**——见 §4。

## 4. TLB：地址翻译的缓存

每次内存访问都要查页表（至少 1 次额外访存，多级则 3-4 次）——翻译比取数还慢！**TLB（Translation Lookaside Buffer）**是 MMU 里的小容量全相联缓存：

```
地址翻译：查 TLB 命中 → 直接得物理地址（1 次访存）
         未命中 → 走页表（慢路径）→ 结果填入 TLB
```

TLB 通常只有 64-1024 项，但命中率 >99%（程序的局部性：短时间内访问集中在少数页）。**TLB miss 的代价**：多级页表要 4 次额外访存——这就是"大内存随机访问慢"的硬件根源。

优化：**Huge Pages（大页）**（2MB/1GB 页）——TLB 一项覆盖 512 个 4KB 页，数据库/JVM 大堆场景显著降 miss。

## 5. 缺页异常：按需调页的完整流程

```
1. 访问的页不在内存（PTE 存在位=0）→ MMU 触发缺页中断
2. 内核查找：虚拟页在磁盘吗？
   ├─ 在（换出过）→ 选牺牲页置换出 → 从磁盘读入目标页 → 更新 PTE
   └─ 不在（首次访问）→ 分配页框（可能要回收）→ 清零 → 更新 PTE
3. 返回用户态，重新执行那条内存访问指令（透明重试）
```

**按需分页（demand paging）** 的意义：进程启动不加载全部代码——只加载要用的页；`mmap` 大文件、Linux 的 exec 加载 ELF 都靠它。**写时复制（COW）** 是它的变种：`fork()` 后父子共享页（只读），谁先写谁触发缺页并复制——`fork` 从"复制整个地址空间"变成 O(1)。

## 6. 页面置换算法：谁是牺牲页

| 算法 | 规则 | 问题 |
| --- | --- | --- |
| OPT 最佳 | 换最久不会用的（理论下界） | 无法实现（需预知未来） |
| FIFO | 换最早进来的 | Belady 异常（加内存反而更多缺页） |
| LRU 近似 | 换最久未访问的 | 精确 LRU 硬件成本高 |
| **时钟算法（CLOCK）** | 循环扫访问位：0→换出，1→给第二次机会 | 实用近似 LRU，Linux 内核基础 |

Linux 实际用 **LRU + 活跃/非活跃双链表 + 二次机会**的变体（还有对文件页/匿名页的不同策略）。`vmstat` 的 `si/so` 列显示换入换出——持续非零 = **抖动（thrashing）**：物理内存不够，系统在疯狂换页而非干活。

## 7. 内存映射与 swap

- **mmap**：把文件/设备映射进地址空间，读写文件 = 读写内存（共享内存 IPC 就是 mmap 两进程映射同一区域）
- **swap 分区**：把不活跃的匿名页（堆/栈）整页换到磁盘——Linux 用 zswap/zram（压缩后放内存）缓解磁盘 swap 的慢

**现代趋势**：内存越来越便宜 + SSD 太慢，很多服务器干脆关 swap（`vm.swappiness=0`）——用 OOM 明确失败替代无声抖动。容器（K8s）里 swap 管理更是经典运维议题。

## 8. 陷阱速查表

| 现象 | 原因 | 修法 |
| --- | --- | --- |
| si/so 持续高、系统假死 | 内存不足抖动 | 加内存 / 调 swappiness / 查泄漏 |
| 大页访问仍慢 | TLB miss（页表遍历） | 开 Huge Pages（数据库/JVM） |
| fork 大进程瞬间内存翻倍 | 传统 fork 复制（已用 COW 缓解） | 确认内核 COW；避免无谓 fork |
| mmap 写入没落盘 | 页还在缓存/未 msync | fsync / MAP_SYNC |
| 随机访问大数组极慢 | TLB miss + 缓存 miss 叠加 | 分块遍历（顺序访问提高局部性） |
